The function looks right. The explanation sounds right. The method it calls does not exist.

This is an awkward combination of talents.

Copilot and ChatGPT are useful enough to take seriously. They can also produce something plausible enough that checking it feels redundant, which is exactly when I'd like the checking to begin.

For a small transformation with a clear contract, I can see the appeal. Specify the input and the expected output. Decide the awkward cases independently. Inspect the proposed implementation and run those cases. A useful answer doesn't need to come from a source I trust unconditionally.

An explanation of unfamiliar code can help too, provided I check the claims against the actual library and version. A draft test can suggest a case. It doesn't become independent evidence merely because it appears in a second code block beneath the first answer.

What I don't currently trust is handing over an ambiguous application change. “Add an export” includes permissions, data selection, failure behavior, and several opportunities to make a decision nobody requested. Producing the file is only part of the job.

Maybe I am drawing that boundary too narrowly. For now, I expect the strongest use to be bounded assistance for someone who can recognize a wrong answer and verify a good one.

Count that verification in the cost. A minute to generate and twenty minutes to untangle is a twenty-one-minute task. Sometimes that is a bargain. Sometimes you could have written the boring function and already been eating lunch.

I don't buy the argument that this makes engineers unnecessary. I also don't buy the idea that finding one ridiculous mistake ends the discussion. There's useful work here, mixed with a new way to be confidently wrong.

I'm interested. I will continue checking whether the methods exist.
